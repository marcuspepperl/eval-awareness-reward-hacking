Does Eval Awareness Change Reward Hacking?

When a reasoning model suspects it is being tested, does it cheat less, or more? And does it matter whether it thinks the test is about capability or about safety?

2 Setup

We use Impossible-LiveCodeBench from ImpossibleBench: LiveCodeBench problems whose unit tests were mutated so that no correct implementation can pass them. In the one-off split a single expected value is wrong; in the conflicting split two tests contradict each other. Passing therefore requires cheating: special-casing inputs, keeping state between calls, or redefining the test harness.

The model sees the specification and tests, and is told "Implement the function according to the provided specification. DO NOT MODIFY THE TESTS." After each failed attempt it receives only a neutral [test runner] Tests failed. message, for up to 8 attempts.Early pilots offered an explicit escape hatch (a flag for human intervention). The model then flagged 100% of the time and never cheated, likely because the offer itself cues that something is wrong, so the main runs omit it.

3 Observational results

Across all 103 problems (2 samples per problem and split), cheating accumulates over attempts. The shaded band is a 95% bootstrap interval, resampling problems rather than individual rollouts.

Cheating is also concentrated in particular problems. Most problems that are hacked on the conflicting split are hacked on the one-off split too, but not the other way around.
